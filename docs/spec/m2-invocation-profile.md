# M2 Invocation Profile

Status: `CONSTRUCTION BASELINE`

This profile turns the frozen M1 affine contract into one bounded cross-process experiment. It is an
implementation specification for M2, not a general RPC, lifecycle, runtime, or plugin specification.

## Fixed slice

| Concern | M2 profile |
| --- | --- |
| Host API | Java 17 `AffineBatchMapper` with JPyxis-owned input, output, and failure types |
| Invocation authority | Java `InvocationManager` |
| Contract authority | frozen M1 contract and Java/Python M1 validators |
| Carrier | one unary Protobuf request and worker report |
| Transport | gRPC over loopback, plaintext for the local reference lab only |
| Definition capability | one statically configured Python affine definition |
| Execution | NumPy on CPU |
| Topology | one Java client process and one Python worker process |
| Side effects | none |
| Retry | none |
| Acceptance | external harness plus offline verifier |

## Coordinates

Every dispatched attempt carries:

- exact contract identity and digest from `spec/m1/identity.lock.json`;
- immutable definition identity and SHA-256 digest;
- invocation, attempt, and trace identifiers generated by the Java host;
- an absolute deadline instant;
- the selected definition and runtime capability identities and versions.

The worker echoes the identities it observed. The host rejects missing or mismatched coordinates
before considering the returned value.

## Carrier mapping

The wire schema represents the reference input and output explicitly. It is not an open object map.
A tensor carries a declared dtype, layout, dimensions, and flattened numeric values so both the host
and worker can map it into the frozen M1 value model and run the relevant validator.

The worker report contains either a raw affine output or a typed failure observation. It does not
contain an invocation terminal state or acceptance verdict.

## Public Java contract

The reference host surface is conceptually:

```java
interface AffineBatchMapper {
    AffineBatchResult execute(AffineBatchInput input, InvocationOptions options)
        throws JPyxisInvocationException;
}
```

The input and result types are immutable JPyxis host values. `InvocationOptions` supplies the bounded
deadline and optional cancellation signal. Public exceptions expose stable JPyxis category and code,
coordinates, and ambiguity flags; they do not expose gRPC exceptions.

## Observation order

The M2 recorder recognizes this ordered path:

```text
INVOCATION_ACCEPTED
→ INPUT_VALIDATED
→ ATTEMPT_PINNED
→ DISPATCH_STARTED
→ WORKER_REQUEST_OBSERVED
→ WORKER_INPUT_VALIDATED
→ RUNTIME_STARTED
→ RUNTIME_COMPLETED or WORKER_FAILURE_REPORTED
→ RESPONSE_OBSERVED
→ OUTPUT_VALIDATED
→ one terminal commitment
```

Failure paths may stop early. A worker observation can arrive after the host terminal commitment and
is then retained with `late: true`; it cannot be inserted earlier to fabricate a valid transition.

## Acceptance matrix

| ID | Stimulus | Required invocation outcome | Required independent evidence |
| --- | --- | --- | --- |
| `success_exact` | valid two-row deterministic input | `SUCCEEDED` | exact affine oracle matches typed result |
| `bad_rank` | rank differs from `[B,4]` | `FAILED / CONTRACT_FAULT` | no worker request or runtime start |
| `bad_shape` | second dimension differs from `4` | `FAILED / CONTRACT_FAULT` | no worker request or runtime start |
| `bad_dtype` | carrier value declares non-float32 input | `FAILED / CONTRACT_FAULT` | no runtime start |
| `bad_batch_bound` | `B` outside `1..32` | `FAILED / CONTRACT_FAULT` | no worker request or runtime start |
| `bad_non_finite_scalar` | non-finite scale or bias fixture | `FAILED / CONTRACT_FAULT` | no worker request or runtime start |
| `malformed_output` | worker emits wrong row count or shape | `FAILED / INVOCATION_FAULT` | raw output retained; no success commitment |
| `definition_failure` | prepared definition is unavailable | `FAILED / DEFINITION_FAULT` | worker report remains non-authoritative |
| `definition_identity_mismatch` | worker selection differs from pinned definition | `FAILED / CONTRACT_FAULT` | runtime does not start |
| `invalid_worker_failure` | worker sends an undeclared failure envelope | `FAILED / CONTRACT_FAULT` | worker code does not become public API |
| `worker_coordinate_mismatch` | returned output is tied to another coordinate | `FAILED / CONTRACT_FAULT` | produced value cannot become success |
| `worker_unavailable` | no process listens on pinned endpoint | `FAILED / TRANSPORT_FAULT` | dispatch occurred; no invented worker execution |
| `transport_interrupted` | worker exits after observing request | `FAILED / TRANSPORT_FAULT` | unknown remote completion is explicit |
| `runtime_failure` | affine execution raises | `FAILED / RUNTIME_FAULT` | failure is distinct from definition and transport |
| `deadline_before_dispatch` | deadline already expired | `TIMED_OUT` | no dispatch or worker execution |
| `deadline_during_execution` | host deadline wins while worker is running | `TIMED_OUT` | late/continued execution cannot rewrite terminal state |
| `cancel_late_result` | caller cancellation wins; worker later computes | `CANCELLED` | late result is retained and discarded |
| `bundle_missing` | required observation/file removed | unchanged source invocation fact | verifier returns `INCONCLUSIVE`, never `PASS` |
| `bundle_truncated` | JSONL or JSON is cut | unchanged source invocation fact | verifier returns `INCONCLUSIVE`, never `PASS` |
| `bundle_reordered` | required event order is impossible | unchanged source invocation fact | verifier returns `FAIL` or `INCONCLUSIVE` |
| `bundle_corrupt` | recorded bytes differ from digest | unchanged source invocation fact | verifier returns `FAIL` |
| `bundle_conflicting` | coordinates or terminal observations conflict | unchanged source invocation fact | verifier returns `FAIL` |
| `recorder_failure` | evidence recorder cannot complete | invocation follows runtime facts | acceptance cannot become `PASS` |
| `verifier_failure` | verifier cannot complete | invocation fact remains readable | acceptance is `INCONCLUSIVE` |

`bad_dtype` may use a boundary probe because the normal typed Java API makes a non-float32 affine
input unrepresentable. That probe is test infrastructure, not a generic public mapper escape hatch.

## Evidence bundle version 1

Each completed scenario directory contains immutable copies or explicit absence records for:

```text
manifest.json
contract.json
definition-artifact.py
request.json
host-observations.jsonl
worker-observations.jsonl
raw-worker-report.json
authoritative-outcome.json
oracle.json
verdict.json
```

The manifest records file digests, source and build coordinates, OS/architecture/toolchains,
dependency versions, contract and definition bytes/digests, selected capability identities,
invocation/attempt/trace identifiers, bare-process launch entry points, evidence completeness, and
explicitly unproven claims.

The offline verifier receives only a completed bundle directory. It checks file integrity, coordinate
agreement, one terminal outcome, possible event order, contract-valid output, exact affine semantics,
and verdict consistency. Missing evidence is never inferred from a success label.

## M2 construction order

1. freeze the carrier and public host mapping;
2. implement host-side validation and the single terminal decision;
3. implement the separate worker and worker-side validation;
4. add normal and named fault paths;
5. retain raw evidence before writing summaries;
6. implement the offline verifier;
7. execute the complete matrix serially;
8. review M1 dependency preservation and M2 claims before any freeze.

## Explicitly unproven

M2 cannot prove general runtime replaceability, deployment lifecycle, retries, multi-worker routing,
durable recovery, performance, production readiness, security isolation, accelerator support,
multi-host behavior, or clean-machine reproducibility.
