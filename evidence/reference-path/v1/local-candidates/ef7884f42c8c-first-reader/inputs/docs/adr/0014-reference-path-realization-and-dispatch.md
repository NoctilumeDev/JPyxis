# ADR-0014: Reference Path Realization and Dispatch

Status: `REVIEWED CANDIDATE · CONTRACT FREEZE REQUIRED BEFORE RUNTIME`

## Context

Qualified Audit A v3 rechecks the repaired M4/M5 local guard premises and retains the remaining
public seam: M4's pin, M5's plan and M2's real invocation do not yet associate one deployment,
artifact, environment, Runtime binding and worker before dispatch. Existing fixture and clean
baseline qualification cannot establish that stronger product-path claim.

## Decision

Define one versioned outer contract for the existing stateless float32 affine CPU witness. Bind
retained definition/contract bytes, a minimal native-package Environment specification, the existing
M3 requirement/binding and one fresh host-owned Python launch. Independently observed construction,
host/worker facts and a real representative M2 invocation feed a computation-domain Control decision.
Only the exact qualified realization may enter M4 admission, warmup, STANDBY and activation.

Prequalifying the constructed candidate permits failure cleanup by its actual launch owner without
adding an M4 abort state or treating an unadopted alias as an owned Runtime handle. M4, M5 and M2
retain their distinct owners and frozen meanings. Private realization-specific M5 assemblies can
reuse existing selection; the composition owner still compares the selected plan to the actual pin
and current instance atomically before wire dispatch. Explicitly bind both M5 and M2 coordinates,
without changing either module's IDs or trusting a worker-supplied verdict.

Preserve caller waiting, execution observations and logical terminal authority separately. After
uncertain dispatch, the first profile retains OUTCOME_UNKNOWN without automatic retry. A late
validated success remains a source observation. Rollback uses immutable validated operands and a
new qualified launch/instance/handle. Physical cleanup requires independent observation of every
owned child; a capability's success label is insufficient.

## Consequences and limits

The first Environment fields follow actual CPython/NumPy/gRPC executable requirements and pinned
predecessor inputs. They do not introduce another Runtime identity, a dependency solver, resource
grant, OS policy or generic environment builder. Fresh processes are a bounded reference isolation
choice, without an adversarial-code security guarantee or a universal Runtime requirement.

Narrow composition, byte-snapshot and transport seams may be added only under the separately frozen
contract, preserving predecessor behavior and the old normative inputs. The implementation must
reuse M2/M3 execution, M4 lifecycle and M5 logical decisions; a parallel replacement framework is
not authorized. Contract authority is an exact protected main and normative blobs, followed by a
separate qualified freeze record. This introduces no new baseline milestone or tag authority.

The actual-path matrix and semantic evidence mutations qualify implementation later. Model checks,
document labels and green predecessor CI do not establish real execution, process freshness,
cleanup, clean reproduction or product readiness. A larger counterexample or authority conflict
stops construction before the next boundary is widened.
